# PLC 시뮬레이터 · 실시간 모니터링 · MES 연계 (D-222 ~ D-227)

도입기업이 아직 **레이저커팅기 PLC 의 IP 와 태그맵을 주지 않았다**(D-169 · D-176). 실물을 못 붙이는 동안
PLC 쪽을 세워서 수집 전 구간(PLC 레지스터 → Gateway → 수집 API → PostgreSQL → 화면 → MES)을 돌린다.
**이 값은 전부 시뮬레이션이다.** `DAT_TIMESERIES.COLLECT_PATH = '시뮬레이터(PLC→Gateway)'` 로 남고,
화면에는 `시뮬레이터 데이터 (D-174)` 배지가 뜬다.

---

## 1. 3분 시연

한 줄로 서버와 시뮬레이터를 **함께** 띄운다 (D-230). Ctrl-C 한 번에 둘 다 내려가고 작업지시도 되돌린다.

```bash
make demo                                  # 포트 8020 · 2초 주기 · 작업지시 WO-2017-0002
make demo WO=WO-2017-0009 POLL=1 ANOMALY=0.1 FAULT_EVERY=30
```

따로 띄우려면:

```bash
make run                                   # 터미널 1 — 서버 (포트 8020)
make plc-wo-start WO=WO-2017-0002          # 터미널 2 — 레이저커팅 작업지시 하나를 진행 상태로 (시험용, D-226)
make plc-run POLL=2 ANOMALY=0.05 FAULT_EVERY=30   # 터미널 2 — 2초마다 생성·적재. Ctrl-C 로 멈춤
```

브라우저에서 **003 설비상태 모니터링** 또는 **022 공정 데이터 모니터링**을 연다.
상단 `레이저커팅기 실시간` 패널이 2초마다 갱신된다 — 가동상태·태그 8종·추이·금일 집계·작업지시·자동 실적·알림.

끝나면:

```bash
make plc-wo-finish WO=WO-2017-0002         # 작업지시를 완료로 되돌리고 선언을 거둔다
```

> `make gate` 는 **깨끗한 DB** 에서 잰다(`make db-reset`). 데몬이 남긴 런타임 행(신호·시계열·버퍼·알림·자동 실적)은
> 게이트의 G-11 0건 판정과 섞인다 — 시연 뒤에는 `make db-reset` 을 한다.

## 2. 연속 모드가 하는 일 (`tools/plc_simulator.py --daemon`)

| 주기마다 | 무엇 |
|---|---|
| ① 생성 | 태그 8종(작업시간·수량·가동상태·알람·속도·압력·전류·온도) — 정본이 적은 것뿐이다 |
| ② PLC 스캔 | `work/plc_device.db` 레지스터에 쓴다 (장비 메모리 — 우리 DB 가 아니다) |
| ③ Gateway 폴링 | 미전송분을 `POST /api/ingest/plc` 로 올린다. **적재 성공 뒤에만** 보냄 표시 |
| ④ 단절 | `--fault-every N --fault-len M`: N 주기마다 M 주기 동안 Gateway↔클라우드 단절 → `IF_GATEWAY_BUFFER` → 복구 시 재전송 (유실 0) |
| ⑤ 상태 | 가동 → 대기/정지 전이, `--anomaly-rate` 확률로 알람 에피소드(전류·온도 임계 초과값 + `AL-CUR-HI`) |

옵션: `--poll-sec`(기본 .env `KYUNGDONG_PLC_POLL_SEC`) · `--max-cycles`(시험용 자동 멈춤) · `--work-order WO-…`(현장POP 지정 흉내) · `--via inproc`(HTTP 없이).

**시뮬레이션 가정**(정본에 없다): 정상 범위 속도 1000~1300 mm/min · 압력 8~12 bar · 전류 18~26 A · 온도 35~55 ℃,
조각당 약 90초, 상태 유지 주기 가동 40~120 / 대기 3~10 / 정지 5~20. 실물 값이 아니다.

## 3. 실시간 패널 (D-223)

- 화면 **003 · 022** 안에 있다 — 새 화면을 만들지 않았다(화면 45 고정).
- 단일 소스 `GET /api/ingest/live?equip=EQ10&n=30`. 화면 첫 렌더와 갱신이 **같은 함수**를 본다.
- 갱신 주기 = PLC 수집 주기(최소 2초). 버튼으로 끄고 켠다.
- **실패를 숨기지 않는다** — 401/403/503 이 상태 코드째 패널에 뜨고, 5회 연속 실패면 멈춘다.
- 0건이면 `미수집 (D-06)`. 가동률은 분모 0 이면 `—`. 값을 만들지 않는다.

## 4. MES 연계 (D-224)

```
PRC_EQUIP_SIGNALS.WORK_ORDER_ID  ← 어느 작업지시의 신호인가
PRC_PERFORMANCES(자동(PLC))       ← 신호에서 도출한 실적 (작업지시 × 수집일 1행)
AGT_RECOMMENDATIONS(알림추천)     ← 장비 알람 에피소드(가동상태 `알람`) → 041 알림 화면
```

| 상황 | 결과 |
|---|---|
| payload 에 `work_order_id` (현장POP 지정) | 검증(P40 · 사내 · 미완료) 후 사용. 틀리면 **422 + 배치 롤백** |
| 지정 없음 · 진행 중 P40 지시 **1건** | 자동 매핑 |
| 지정 없음 · 진행 중 P40 지시 **0건 / 2건 이상** | **붙이지 않는다.** `WORK_ORDER_ID` NULL, 패널에 이유 표시 |

자동 실적은 저장이 아니라 **도출**이다 — 같은 배치를 다시 보내도 두 배가 되지 않는다.
**불량 수량은 비운다.** PLC 는 양·불을 판정하지 않는다 — 검사(품질 담당)가 정한다.

## 5. 하지 않은 것 · 못 하는 것

| | 왜 |
|---|---|
| 임계값 비교·경고 (D-225) | `PRC_STD_CONDITIONS(P40)` 0건(도입기업 제공, D-59) · 알림기준 "임계값 미확정". 임계를 지어내지 않는다. 표준조건이 들어오면 `mes.threshold_check()` 가 바로 편차를 낸다 |
| 실물 PLC 레지스터 주소 | `SIM-D0001…` 은 시뮬레이터 주소다. 실물 XGB 주소는 **PLC 태그맵**(D-176)이 있어야 안다 |
| 운영(prod) 수집 | `IF_DEVICE_REGISTRY.IP_ADDRESS` 가 비어 있어 403 이다(D-168). 화면 029 에 장비 IP 를 넣으면 열린다. 시뮬레이터 IP 는 `make plc-register` 로 넣되 **선언과 함께** 들어간다(D-174) |
| 작업지시 생성·상태 변경 화면 | 45화면에 없다. `make plc-wo-start/finish` 는 **시험용**이고 선언을 남긴다(D-226) |
