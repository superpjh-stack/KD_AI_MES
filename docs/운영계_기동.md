# 운영계 기동 안내 (D-204~D-209)

개발 프로파일과 **동작이 다릅니다.** 운영에서 확인된 것만 적었습니다 — 안 해본 것은 안 적었습니다.

---

## 1. 개발과 무엇이 다른가

| | 개발(dev) | **운영(prod)** |
|---|---|---|
| 로그인 | **안 한다** — 세션 없이 `시스템 관리자` | **필수** |
| 미인증 화면 요청 | 그냥 열린다 | **`/login` 으로 보낸다** (303) |
| `/` (홈) | 열린다 | **로그인 필요** |
| 쿠키 | 평문 가능 | **`Secure`** — HTTPS 아니면 로그인 자체가 안 된다 |
| 역할 전환 | `?as=EXEC` 로 가능 | **불가** (세션 역할만) |
| 헤더 표시 | `로그인 아님 — 개발 전환` | 계정명 · 역할 · **로그아웃** |

개발에서 `?as=` 로 역할을 바꿀 수 있는 것은 **개발 전용**입니다. 운영에서는 그 분기가
아예 동작하지 않습니다.

---

## 2. 기동 전 준비

### ① 세션 비밀키 — **없으면 앱이 뜨지 않습니다**

```bash
export KYUNGDONG_SESSION_SECRET="$(python3 -c 'import secrets;print(secrets.token_urlsafe(48))')"
```

이 값이 바뀌면 **기존 로그인 세션이 전부 끊깁니다.** 서버 재시작 때 유지되도록
환경 파일·시크릿 매니저에 둡니다. **저장소에 넣지 마십시오.**

### ② HTTPS 종단 — **선택이 아닙니다**

운영에서 세션·CSRF 쿠키에 `Secure` 가 붙습니다. 평문 HTTP 로 열면 브라우저가 쿠키를
저장하지 않아 **로그인이 성립하지 않습니다** (증상: 로그인 눌러도 403 `CSRF 토큰이 없거나
유효하지 않습니다`).

리버스 프록시(Nginx 등)에서 TLS 를 끊고 앱으로 넘기는 구성이라면:

```bash
make run-prod PORT=8020 HOST=127.0.0.1 PROXY_IPS=127.0.0.1
```

`--proxy-headers` 로 `X-Forwarded-Proto` 를 읽습니다. **`PROXY_IPS` 에 실제 프록시 IP 를
적으십시오** — 기본값은 로컬뿐입니다.

> ⚠ TLS 버전·암호 스위트는 **사업계획서에 값이 없습니다**(D-15). 저희가 임의로 정하지
> 않았습니다. 프록시 설정은 도입기업 보안 기준에 맞춰 주십시오.

### ③ 데이터베이스

```bash
make db-schema      # 최초 1회
make db-seed        # 코드 마스터·계정·기준정보
```

`make db-reset` 은 **전부 지웁니다.** 운영에서는 쓰지 마십시오.

## 3. 첫 로그인

계정 비밀번호는 **계정을 처음 만들 때 한 번만** 난수로 출력됩니다(저장소에 리터럴 0건).
그 출력을 놓쳤거나 분실했으면 재발급합니다.

```bash
make ops-accounts                      # 계정·역할·잠금 상태 (비밀번호는 안 나옴)
make ops-password LOGIN=admin          # 재발급 — 화면에 1회만 출력
make ops-password LOGIN=admin UNLOCK=1 # 잠긴 계정을 함께 해제
```

- 발급된 비밀번호는 **그 출력에만** 나옵니다. 파일·로그 어디에도 남지 않습니다.
- `SYS_ACCESS_LOGS` 에 **누가 언제 어느 계정을 바꿨는지**는 남습니다. 비밀번호 자체는 아닙니다.
- 첫 로그인 뒤 **화면에서 바꾸십시오** (로그인 화면의 비밀번호 변경).

계정 6종: `admin`(시스템 관리자) · `exec`(총괄PM/경영자) · `prod`(공장장·생산관리) ·
`quality`(품질·RCMS) · `operator`(현장 작업자) · `supplier`(공급기업 운영담당).

## 4. 기동 뒤 확인 (5가지)

```bash
curl -sI https://<호스트>/dsh/001 | head -1     # → 303, Location: /login?next=...
curl -sI https://<호스트>/login   | head -1     # → 200
```

1. 업무 화면이 **`/login` 으로 간다** (403 이 아니다)
2. 로그인 후 **원래 가려던 화면**으로 간다
3. 헤더에 **계정명 · 역할 · 로그아웃**이 보인다
4. 헤더 환경 배지가 **`prod`** 다 (`dev` 면 환경변수가 안 먹은 것)
5. 로그아웃하면 다시 막힌다

## 5. 수집 장비 (PLC · 현장POP)

**아직 열려 있지 않습니다.** 운영에서 `POST /api/ingest/plc` 는 **403** 입니다 —
장비를 알아볼 방법이 없기 때문입니다(D-168·D-169).

`IF_DEVICE_REGISTRY.IP_ADDRESS` 가 비어 있습니다. 화면 **029 시스템 설정**의
수집 장비 등록에 **레이저커팅기 PLC · 현장POP 의 IP** 를 넣으면 그 경로가 열립니다.
저희가 시험용 IP 로 **실제로 열리는 것을 확인**했습니다.

> IP 대조는 완전한 인증이 아닙니다. 같은 IP 의 다른 프로그램은 가려내지 못합니다 —
> 사업계획서 9.2 의 VPN·폐쇄망 안에서 쓰는 보조 수단입니다. 장비별 비밀키 방식을
> 원하시면 **설계서에 칸을 추가**해야 합니다(현재 11컬럼에 인증 칸 없음, 컬럼 762 고정).

## 6. 운영에 올리기 전에 아셔야 할 것

지금 데이터베이스에는 **합성 데이터**가 들어 있습니다. 화면 하단에
`합성 데이터 기준 (D-131)` 배지가 그 사실을 나릅니다.

- **실측**: 프로젝트 12건 · 도면 341건 · 고객사 19종
- **합성**: BOM · 자재LOT · 입고 · 재고 · 작업지시 · 공정실적 · LOT추적 · 검사 · 출하
- **가설**: 품목 코드 179종 (과거 견적서에서 관측)

실데이터로 바꾸면 배지는 사라집니다. **그 전까지 이 화면의 수치를 성과 실적으로
인용하지 마십시오.**

각 화면에는 **미비 항목** 표가 있습니다 — 무엇이 왜 비어 있고, 무엇이 있어야 채워지며,
그때까지 어떻게 하고 있는지가 적혀 있습니다. 전체 목록은 **029 시스템 설정**에 모입니다.
