# contracts/missing-policy.md — 결측·지연 판정 규약 (G-10)

> goal.md §2.2 G-10 이 이 문서를 가리키는데 **없었다**(QA2 DEF-QA2-007). 아키텍트 누락이다.
> 검사기가 분모·분자를 각자 정하면 같은 DB 에서 다른 수치가 나온다. 여기서 한 번만 정한다.

## 0. 먼저 — 이 사업에는 목표치가 없다

**사업계획서에 시계열 동기화율 목표가 없다**(D-09). 2.7.4 는 정확성·정합성·연계성 **각 85%** 만 정했고
시계열 항목은 없다. 따라서 G-10 은 **실측만 보고**한다. 목표 없는 것을 있는 척하지 않는다.

직전 사업(광성정밀)의 값(동기화율 85% · PTP 오차 1s · 1s 리샘플링)은 **그 사업의 것**이다. 가져오지 않는다.

## 1. 수집 지점은 2개소뿐이다 (D-06)

| 지점 | 대상 | 프로토콜 |
|---|---|---|
| 레이저커팅기 **Master PLC** 1 | 작업시간·수량·가동상태·알람·속도·압력·전류·온도 | Ethernet / OPC-UA |
| **현장POP(터치PC)** 1 | 작업·검사 입력값 | TCP/IP |

**그 외 공정은 수집 대상이 아니다.** 결측률 분모에 넣지 않는다 — 없는 것과 못 받은 것은 다르다.
수집 대상 밖은 결측이 아니라 `미수집 (D-06)` 이다.

## 2. 분모·분자

### 2.1 수집 결측률

> **초판이 두 군데 틀렸다.** QA2 가 실측으로 반박했다(DEF-QA2-013·014). 아래가 정정본이다.

```
분모 = (측정 구간 길이 ÷ PLC_POLL_SEC − 비가동 틱 − 상태미상 틱) × 정본 태그 수
       · 측정 구간은 IF_DEVICE_REGISTRY 에 등록되고 USE_YN='Y' 이며 DEVICE_TYPE='PLC' 인 장비만
       · **현장POP(터치PC)은 자동 폴링 대상이 아니다 — 수동 입력이므로 분모에서 뺀다**
       · 태그 수는 **정본 태그표**(`ingest/tags.TAGS`, 8종)에서 온다
분자 = IF_PLC_SIGNALS 의 distinct(태그, 수집시각)
결측률 = 1 − 분자 ÷ 분모
```

**왜 태그 수를 수집 원장에서 뽑으면 안 되는가 (DEF-QA2-013)**
초판은 "태그 수는 `IF_PLC_SIGNALS` 에 정의된 활성 태그" 라고 적었다. **순환이다** —
수집 결과에서 분모를 뽑으면 **태그가 통째로 유실될 때 분모도 같이 줄어** 결측률이 구조적으로 0 에 수렴한다.
QA2 실측: 0건 상태에서 `count(distinct TAG_NAME)` = **0** → 분모가 영원히 0.
**분모는 기대값이지 실측값이 아니다.** 정본 태그표에서 온다. 두 값을 **함께 출력**해 차이를 드러낸다.

**왜 분자가 `IF_PLC_SIGNALS` 인가 (DEF-QA2-014)**
초판은 "`PRC_EQUIP_SIGNALS` + `DAT_TIMESERIES` 중복 제거 후" 라고 적었으나 **세 표의 행 단위가 다르다.**
QA2 5주기 실측: `PRC_EQUIP_SIGNALS` **5** · `DAT_TIMESERIES` **30** · `IF_PLC_SIGNALS` distinct(태그,시각) **40**.
분모가 (구간÷주기)×태그 이므로 **단위가 맞는 것은 `IF_PLC_SIGNALS` 뿐**이다.

**결측률은 두 가지가 있다 (DEF-QA2-015)**
| 지표 | 뜻 | 위치 |
|---|---|---|
| **미적재 비율** | 기대 건수 대비 안 들어온 것 | **이 규약의 결측률** (정본) |
| 값 결측 비율 | 들어왔으나 값이 비어 있는 것 | `부가 실측` 으로 병기 |
둘을 섞어 하나의 수치로 보고하지 않는다.
**장비가 꺼져 있던 구간은 분모에서 뺀다.** 가동하지 않은 시간의 미수집은 결측이 아니다.
판단 근거는 `PRC_EQUIP_SIGNALS` 의 가동상태 태그다. 상태를 모르는 구간은 **결측률에서 제외하고 그 사실을 적는다**.

### 2.2 지연
```
지연 = 수집 시각(장비) 대비 적재 시각(DB) 차이
Gateway 버퍼 재전송분은 '지연'이지 '결측'이 아니다 — IF_GATEWAY_BUFFER 에 흔적이 남는다
```

### 2.3 순서 보존
**라이브 구간과 재전송 구간을 나눠서 본다**(QA2 실측 교훈).
store-and-forward 특성상 재전송분이 뒤늦게 들어오면 **전역 타임스탬프 순서는 역전된다** — 이것은 정상이다.
위반은 **같은 구간 안에서** 순서가 뒤집힌 경우만이다.

## 4. '정상 데이터' 의 조작적 정의 (G-09 정확성)

**사업계획서 2.7.4 는 "정확도 = (정상 데이터 수 ÷ 전체 데이터 수) × 100" 이라고만 적고
'정상' 을 정의하지 않았다**(QA2 DEF-QA2-012). 정본에 없으므로 **조작적 정의**를 여기 박아 둔다 —
지어낸 기준이 아니라 **명시된 기준**이라는 뜻이고, 도입기업 확인 대상이다.

**정상 = 아래를 모두 만족**
1. 코드성 FK **29건**(`contracts/db-schema.md` §3)이 전부 `BAS_COMMON_CODES(CODE_GROUP, CODE_VALUE)` 에 있다
2. NOT NULL 컬럼에 값이 있다
3. 물리 FK 98건이 실제 행을 가리킨다
4. 수치 컬럼이 단위 표준(mm·kg·℃·A·초) 범위 안에 있다 — **범위 표가 정본에 없으므로 이 항목은 판정에서 제외하고 그 사실을 적는다**

## 5. 분모가 0일 때

**0% 도 100% 도 아니다. `판정 불가` 다.**
현재 `EST_PROJECTS` · `BAS_QUALITY_STANDARDS` · 코드 그룹 `품목`·`재질`·`고객사` 가 0건이라
G-08·G-09·G-10 의 분모가 서지 않는다(D-47 · D-56).
**임시 데이터를 넣어 85% 를 만들지 않는다.** 도입기업에서 목록을 받을 때까지 `차단` 이다.

## 6. 동시 변경 감지 (§10-17)

측정 중 다른 에이전트가 쓰면 결과가 오염된다. 검사기는 **FAIL 이 아니라 `판정 불가`** 를 낸다.
감지는 두 신호로 한다 — ① 측정 전후 무관 표 행수 스냅샷 대조 ② 되돌아온 변동(롤백 자국).
